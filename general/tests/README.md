# Проверки подсистемы тестовых ботов

Обычные скрипты на голых `assert`, без pytest — его нет ни в образе, ни в
зависимостях, а тащить его ради десятка проверок и пересобирать образ дороже,
чем оно того стоит.

Запуск изнутри контейнера:

```bash
docker exec -it orderflow_general python -m tests.run_all
docker exec -it orderflow_general python -m tests.test_price_cache
```

Или разово, без поднятого стека:

```bash
docker run --rm --entrypoint python \
  --network marketmaker-orderflow_redis_network \
  -e PYTHONPATH=/opt/services/app/src \
  -v "$PWD/general:/opt/services/app/src" -w /opt/services/app/src \
  marketmaker-orderflow-general -m tests.run_all
```

Тесты, которым нужна база или Redis, сами скажут об этом и завершатся с
понятной ошибкой. Чистых проверок на заглушках это не касается — они идут
где угодно.

`python -m tests.test_watched_affordability` — фильтр покупки с номиналом
до `WATCHED_PAIR_MAX_BUY_NOTIONAL_USDT`: Decimal, дробные количества,
оба фильтра лота, минимальный номинал по mark price, граница бюджета,
неполные/устаревшие данные, курс USDC, обновление спецификаций и удаление
недоступных старых/закреплённых пар. Только заглушки, сеть и БД не нужны.


`python -m tests.test_price_freshness` — возраст котировки, некорректная цена,
отсутствие времени, просроченный кэш при зависшем обновлении и переводе часов,
сброс кэша при отказе Redis и восстановление. Сеть и БД не нужны.

`python -m tests.test_price_publication` — Lua на настоящем Redis: повтор
пятичасового ответа BMT, откат времени, дубликат, перезапуск питателя, гонка
издателей, срок ключа от события и исключение плохих событий из истории.
Нужен `PRICE_TEST_REDIS_URL` отдельного тестового Redis; без него проверка
пропускается. Используются уникальные ключи, удаляются только они.


`python -m tests.test_donor_freshness` — публикация с TTL и отзыв, старые
ключи, отмена ожидания без цены, замена конфига, таймаут, цепочки v1/v2/v3
перед сигналом и сохранность уже открытой позиции. Только заглушки.

`python -m tests.test_v3_market_limits` — сохранённые фильтры BMT/AVAX,
MIN_NOTIONAL после округления, оба лота, нулевой рыночный шаг, некорректные
данные, 256 сеток против независимого перебора, стартовая/ленивая загрузка
ограничений и изменение цены перед входом. Только заглушки.


`python -m tests.test_donor_publication` — реальный Redis: TTL публикации,
физическое истечение ключа, возраст метаданных и отзыв ещё живого выбора
циклом воркера. Нужен `DONOR_TEST_REDIS_URL` отдельного тестового Redis.
Без переменной тест пропускается; уникальные ключи удаляются в `finally`.

`test_donor_freshness` также проверяет смену/истечение цены во время
финальной проверки цепочки и завершение дочерних задач при отмене/сбое Redis.
`test_v3_market_limits` проверяет остановку после десяти отказов по номиналу.


`python -m tests.test_donor_scope` — пул стратегий-доноров копибота:
`all` против явного списка, пустой список против «без ограничений»,
неизвестный ключ (пул закрывается, а не раскрывается), сохранение порядка
кандидатов и проставление стратегии строкам парка. Только заглушки.

`python -m tests.test_strategy_rollup_db` — измерения стратегии в свёртках
на настоящей базе: сделки одного бота в одном блоке с разной исполненной
стратегией и разной версией алгоритма не схлопываются в одну строку,
повторный проход перезаписывает блок, а разрезы «по парку» и «по
исполненной стратегии» дают разные цифры и не суммируются. Нужна отдельная
база и `STRATEGY_ROLLUP_TEST_DB=1`; без переменной тест пропускается.
Команды для её создания — в шапке файла.
