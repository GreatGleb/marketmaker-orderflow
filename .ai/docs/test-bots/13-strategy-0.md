# 13. Стратегия 0 — прострелы

Дата: 2026-09-19. Статус: реализована, в рабочей базе не заведена —
ботов нет, сделок нет.

Прострел — резкое движение цены за короткое окно. Что считать резким, за
какое окно смотреть и куда входить, заранее неизвестно, поэтому правила
не зашиты в код: они лежат в `test_bots.strategy_config` и перебираются
так же, как перебираются параметры у `legacy`.

Значения по умолчанию — **не рекомендация**. Они выбраны так, чтобы
стратегия вообще срабатывала на живых данных, и подлежат проверке
экспериментом.

## Чем отличается от legacy

| | `legacy` | `strategy_0` |
|---|---|---|
| вход | пробой заранее выставленного уровня | факт движения за окно |
| уровни | в тиках | в процентах от цены входа |
| ожидание входа | `time_to_wait...`, по умолчанию 1 с | `max_wait_seconds` |
| выход по времени | зашитое правило 30 секунд | `max_hold_seconds` |
| настройки | колонки `test_bots` | `strategy_config` |

Уровни в процентах — не косметика: прострел на 0.5% одинаков по смыслу
на паре с тиком в 0.05% и на паре с тиком в 0.001%, а в тиках это 10 и
500 соответственно.

## Настройки (`strategy_config`)

Разбирает и проверяет их сам алгоритм —
`Strategy0Algorithm.parse_config`. Неизвестный ключ и нечисловое
значение отвергаются: бот с такими настройками не запускается, иначе
опечатка тихо выключила бы параметр.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `schema_version` | 1 | версия схемы настроек; не версия алгоритма |
| `window_seconds` | 5 | окно, за которое набрано движение |
| `move_percent` | 0.5 | что считается прострелом, % от цены |
| `entry_mode` | `continuation` | `continuation` — по движению, `reversal` — против |
| `take_profit_percent` | 0.3 | цель, % от цены входа |
| `stop_loss_percent` | 0.3 | стоп, % от цены входа |
| `max_hold_seconds` | 60 | предел удержания, потом выход по времени |
| `max_wait_seconds` | 300 | сколько ждать прострела, потом новый круг |

Окно скользящее: цена сравнивается с самой старой в пределах
`window_seconds`. Поэтому медленный дрейф той же величины прострелом не
считается — это и отличает событие от тренда.

Если за один тик цена прошла и цель, и стоп, засчитывается стоп: порядок
их достижения внутри тика неизвестен, и считать надо худший исход.

## Как завести парк

```bash
# 1. пары стратегии (свой набор, не общий список)
docker exec -it orderflow_general python -m app.scripts.seed_watched_pairs \
    --strategy strategy_0 --symbols BTCUSDT,ETHUSDT --replace

# 2. парк по сетке правил (app/constants/strategy_0_seed.py)
docker exec -it orderflow_general python -m app.scripts.new_bots \
    --strategy strategy_0 --dry-run
docker exec -it orderflow_general python -m app.scripts.new_bots \
    --strategy strategy_0
```

Сетка — 1080 конфигураций: 5 окон × 4 порога прострела × 2 режима входа ×
3 цели × 3 стопа × 3 предела удержания. Пары раздаются конфигурациям по
кругу, иначе весь парк встанет на одну пару и перебор правил превратится
в перебор её характера.

Окно 1 с и порог 2% добавлены 2026-09-23: трейдер просит 0.5–2% за 1–3
секунды, а прежняя сетка (648 конфигураций) начиналась с двух секунд и
заканчивалась процентом. Сопоставимость это не задело — сделок у
стратегии 0 к тому дню не было ни одной, парк ещё не заводился.

**Односекундное окно требует тикового фида — он включён 2026-09-23.**
В прежнем `!ticker@arr` медианный интервал между тиками одного символа
1.21 с, а `c` там агрегат 24-часового тикера: окно в секунду меряло бы
разницу между двумя соседними тиками, а не движение за секунду. Поэтому
источник переведён на фьючерсный `@bookTicker`
(`MARKET_DATA_SOURCE=futures_ws`, 834 тика/с на 55 парах, цена в Redis
обновляется раз в 50 мс). Перед заведением парка убедиться, что режим
включён — на `ws` эти 216 конфигураций соберут шум. Подробности —
[15-orderflow-plan.md](15-orderflow-plan.md), раздел 7.6.

Повторный запуск дублей не создаёт: ключ конфигурации (`bot_identity`)
включает `strategy_config`.

## Что смотреть в отчётах

```bash
# по парку стратегии
python -m app.scripts.top_bots_report -d 7 -s strategy_0

# по фактически исполненному алгоритму (у копиботов расходится с парком)
python -m app.scripts.top_bots_report -d 7 -es strategy_0
```

Складывать эти два разреза нельзя: одна и та же сделка попадает в оба.

## Чего пока нет

* своего парка копиботов у стратегии нет, и он не нужен: копиботы
  универсальны и с 2026-09-20 берут доноров из любой стратегии (раздел
  5б в [04-bot-types.md](04-bot-types.md)). Сетка стратегии 0 заводит
  только обычных ботов — они и попадают в общий пул доноров;
* собственной политики отбора пар: `pair_policy` у неё `manual`, то есть
  пары задаются явным списком. Отбор по скачкам принадлежит `legacy` и
  для прострелов, скорее всего, не годится;
* проверки, что источник цен вообще пригоден для секундных окон.
  Питатель обновляет `price_snapshot:*` раз в несколько секунд — для
  `window_seconds = 2` это на границе разрешения, и прежде чем верить
  результатам с коротким окном, задержку нужно измерить.
